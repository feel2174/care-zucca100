- [ ] **Step 3: 최소 구현**

`lib/naver.ts` — **아래 포맷은 Task 2 SPIKE로 실측 확정된 값이다**(가정 아님):
```typescript
export type Coords = { lat: number; lng: number };

const BASE = "https://map.naver.com/p/search/";

/** 네이버 지도 검색 URL. 좌표가 있으면 지도 중심을 사용자 위치로 이동시킨다. */
export function buildNaverMapUrl(query: string, coords?: Coords): string {
  const path = BASE + encodeURIComponent(query);
  if (!coords) return path;
  // c=경도,위도,zoom,0,0,0,dh (SPIKE로 확정한 포맷)
  return `${path}?c=${coords.lng},${coords.lat},15,0,0,0,dh`;
}

/** 모바일 네이버 지도 앱 스킴. 앱 미설치 시 호출측에서 웹으로 폴백. */
export function buildNaverAppUrl(query: string): string {
  return `navermap://search?query=${encodeURIComponent(query)}&appname=care.zucca100.com`;
}
```

**접근성 요건(스펙 §10)** — 이 컴포넌트가 고령 사용자와 가장 많이 부딪히는 지점이다:

솔리드 버튼 배경은 `bg-primary`(흰 글씨 AAA 11.95:1) — `bg-accent`는 4.91:1로 미달이라 쓰지 않는다.

`components/LocationFinder.tsx`:
```tsx
"use client";
import { useState } from "react";
import { MapPin, Navigation, Loader2 } from "lucide-react";
import { buildNaverMapUrl } from "@/lib/naver";
import { getSidos } from "@/lib/regions";

export function LocationFinder({ query, label }: { query: string; label: string }) {
  const [status, setStatus] = useState<"idle" | "locating" | "denied">("idle");
  const sidos = getSidos();

  function openNearby() {
    if (!("geolocation" in navigator)) { setStatus("denied"); return; }
    setStatus("locating");
    navigator.geolocation.getCurrentPosition(
      (pos) => {
        const url = buildNaverMapUrl(query, {
          lat: pos.coords.latitude,
          lng: pos.coords.longitude,
        });
        setStatus("idle");
        window.location.href = url; // 같은 탭 이동(포트폴리오 관례: 지도 링크 _blank 미적용)
      },
      () => setStatus("denied"),
      { enableHighAccuracy: true, timeout: 8000 }
    );
  }

  return (
    <div className="tile flex flex-col gap-3 px-4 py-4">
      <button
        type="button"
        onClick={openNearby}
        disabled={status === "locating"}
        className="inline-flex min-h-[48px] items-center justify-center gap-2 rounded-xl bg-primary px-5 py-3 text-[17px] font-bold text-on-primary hover:opacity-90 disabled:opacity-60"
      >
        {status === "locating" ? <Loader2 size={16} className="animate-spin" /> : <Navigation size={16} />}
        내 위치로 {label} 찾기
      </button>

      {status === "denied" && (
        <p className="text-[15px] leading-[1.7] text-muted">
          위치 접근을 사용할 수 없습니다. 아래에서 지역을 선택해 주세요.
        </p>
      )}

      <div>
        <p className="mb-2 flex items-center gap-1.5 text-[15px] font-semibold text-muted">
          <MapPin size={13} className="text-accent" /> 지역으로 찾기
        </p>
        <div className="grid grid-cols-2 gap-2 sm:grid-cols-3">
          {sidos.map((s) => (
            <a
              key={s.slug}
              href={buildNaverMapUrl(`${s.name} ${query}`)}
              className="flex min-h-[48px] items-center justify-center rounded-lg bg-band px-3 py-2 text-center text-[16px] font-semibold text-foreground hover:text-link"
            >
              {s.name}
            </a>
          ))}
        </div>
      </div>
    </div>
  );
}
```

```typescript
import type { MetadataRoute } from "next";
import { SITE } from "@/lib/site";
import { getTargets } from "@/lib/targets";
import { getGuides } from "@/lib/guides";
import { getSidos } from "@/lib/regions";

export default function sitemap(): MetadataRoute.Sitemap {
  const base = SITE.url;
  const urls = [
    "", "/find", "/related/maternity",
    ...getTargets().map((t) => `/target/${t.slug}`),
    ...getGuides().map((g) => `/guide/${g.slug}`),
    ...getSidos().map((s) => `/find/${s.slug}`),
  ];
  const now = new Date();
  return urls.map((u) => ({ url: `${base}${u}`, lastModified: now, changeFrequency: "monthly", priority: u === "" ? 1 : 0.7 }));
}
```

## SPIKE 결과 (Task 2 — 2026-08-20 실측 확정)

**방법**: 헤드리스 Chrome `--headless=new --virtual-time-budget=20000 --dump-dom`으로
`map.naver.com/p/search/...`를 열고, 결과 목록을 담는 `#searchIframe`의 `src`에 어떤 좌표가
전달되는지 관측. 좌표를 바꿔가며 3회 + 쿼리를 바꿔 1회 대조.

**관측 결과**

| 검증 | 주입한 `c=` | iframe이 받은 값 |
|---|---|---|
| 강남 | `127.0276,37.4979,15,0,0,0,dh` | `x=127.0276&y=37.4979` |
| 부산 | `129.0756,35.1796,15,0,0,0,dh` | `x=129.0756&y=35.1796` |
| 좌표 없음(대조군) | — | `x=126.936991&y=37.470614` (= `clientX/clientY`, IP 기반) |
| 쿼리 교체(`주민센터`) | 강남 좌표 | `query=주민센터&x=127.0276&y=37.4979` |

**확정 사항**

1. **최종 웹 URL 템플릿**
   `https://map.naver.com/p/search/{encodeURIComponent(query)}?c={lng},{lat},15,0,0,0,dh`
2. **좌표 동작 여부: 동작함.** `c=`의 좌표가 검색 iframe의 `x`/`y`(= 검색 중심)로 그대로 전달된다.
   역지오코딩 같은 대안은 불필요.
3. **좌표 순서: 경도(lng)가 먼저.** 뒤바꿔도 URL은 정상으로 보이고 지도만 조용히 틀린 곳으로 간다
   → `lib/naver.test.ts`에 순서 회귀 테스트를 고정했다.
4. **쿼리 독립성**: 검색어를 바꿔도 동일하게 동작 → 안마원/주민센터/보건소에 빌더 하나를 재사용.
5. **폴백**: 좌표를 안 넣으면 전국 뷰가 아니라 **IP 기반 위치**로 센터링된다. 권한 거부 시에도
   완전히 망가지진 않지만 IP 위치는 통신사에 따라 크게 틀리므로 **시도 셀렉터 폴백은 유지**한다.
6. **미실측**: 모바일 앱스킴 `navermap://search?query=...&appname=...`. 실기기가 없어 확인 못 함.
   웹 URL을 기본 경로로 두고 앱스킴은 실패해도 웹으로 열리게 설계 → 배포 후 실기기 확인.
7. **부수 관측**: 헤드리스 접근 시 DOM에 `ncaptcha-iframe`이 존재. 실사용자의 링크 이동에는 영향이
   없으나, **이 사이트가 네이버 지도를 스크래핑하거나 서버에서 대신 호출하면 안 되는 근거**다.
   우리는 링크 아웃만 한다.
