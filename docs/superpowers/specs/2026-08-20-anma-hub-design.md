## 1. 사실관계 (조사 확정, 콘텐츠 근거)

핵심: "안마바우처"는 단일 서비스가 아니며 4개 대상의 성격이 다르다.

| 대상 | 역할 | 제도 |
|---|---|---|
| 60세 이상 어르신 | 수혜자 | 시각장애인 안마서비스 바우처 |
| 장애인(지체·뇌병변) | 수혜자 | 시각장애인 안마서비스 바우처 |
| 국가유공자(상이등급) | 수혜자 | 시각장애인 안마서비스 바우처 |
| 시각장애인 | **제공자(안마사)** — 받는 사람 아님 | 의료법 §82 안마사 독점 자격 |
| 산모 | **조건부 수혜자** | 산모라는 신분이 아니라 **질환 입증**으로 자격 판단 (§1.1) |

- 수혜 조건: 근골격계·신경계·순환계 질환 보유. 만 65세↑ = 기초연금/기초생활수급자, 그 외 = 기준 중위소득 140% 이하. 장애인/유공자는 연령무관 중위 140% 이하.
- 서비스: 월 4회 × 12개월 = 연 48회, 회당 60분(찜질 15분 포함). 본인부담 10%(약 4,000~4,200원), 90% 정부 지원.
- 신청: 읍·면·동 주민센터 → 국민행복카드 발급 → 시각장애인 안마시술소 예약. 지자체별 신청기간·서류 상이.
- 안마사 자격: 의료법 §82 + 안마사규칙 §3, 시각장애인만 발급.

### 1.1 질환 요건과 질병코드 (2026-08-20 정정)

**자격의 축은 신분이 아니라 질환이다.** 진단서·소견서에 아래 질병코드(KCD)가 명시되어야
질환 요건을 입증할 수 있다.

| 분류 | 코드 | 예시 |
|---|---|---|
| 근골격계 질환 | `M00 ~ M99` | 관절염, 디스크(추간판탈출증), 오십견, 골반통 |
| 신경계 질환 | `G00 ~ G99` | 신경통, 뇌졸중 후유증 |
| 순환계 질환 | `I00 ~ I99` | 고혈압, 대사증후군 관련 순환계 질환 |
| 기타 | `R81`, `E10 ~ E14` | 요단백, 당뇨 |

**산모 처리 정정.** 초기 스펙은 "산모 = 안마 아님"으로 단정했으나 이는 부정확했다.
산모라는 이유만으로 대상이 되지는 않지만, **산후 근골격계 질환 등을 진단서로 입증하면
만 60세 미만이라도 신청이 가능한 지자체가 있다.** 지역사회서비스투자사업은 지자체 자율사업이라
연령 기준과 인정 질병코드가 지역마다 갈린다.

> 출처 주의: 이 정정의 근거는 개인 블로그 정리글이며 정부 공식 문서가 아니다. 따라서
> **"산모 안마바우처"라는 제도가 있는 것처럼 쓰지 않고**, "질환을 입증하면 가능할 수 있다 +
> 지자체 확인 필수"라는 조건부 서술로만 다룬다. 분기 재검증 시 지자체 공고문으로 교차확인할 것.

## 3. 위치찾기 (★관건)

원칙: 주소 추측·좌표 DB 구축 안 함 → **네이버 지도가 최신 목록·거리순 렌더**. "내 위치"는 브라우저 Geolocation으로 얹는다.

동작:
1. [내 근처 안마원 찾기] → `navigator.geolocation.getCurrentPosition` 좌표 취득.
2. 좌표를 네이버 지도 검색 URL 중심 파라미터에 주입:
   `https://map.naver.com/p/search/시각장애인 안마원?c={lng},{lat},15,0,0,0,dh` → 사용자 위치 중심 + 주변 거리순.
3. 폴백(권한 거부/실패): 시도 드롭다운 선택 → 지역명 넣은 검색 URL. 이 로직이 `/find/[sido]` 페이지와 동일(재사용).
4. 동일 컴포넌트를 쿼리만 바꿔 **주민센터 찾기**("○○ 주민센터")에 재사용.
5. 모바일/PC 감지로 앱스킴(`navermap://`) vs 웹(`map.naver.com`) 분기.

### 3.1 SPIKE 결과 (2026-08-20 실측 — 확정)

헤드리스 Chrome(`--headless=new --dump-dom`)으로 실측 완료. **가정한 포맷이 그대로 동작하므로 대안(역지오코딩)은 불필요.**

네이버 지도는 결과 목록을 `#searchIframe`으로 렌더하는데, URL의 `c=` 좌표가 그 iframe의 `src`에
`x=`/`y=`로 그대로 주입된다:

| 검증 | 주입한 `c=` | iframe이 받은 값 |
|---|---|---|
| 강남 | `127.0276,37.4979,15,0,0,0,dh` | `x=127.0276&y=37.4979` |
| 부산 | `129.0756,35.1796,15,0,0,0,dh` | `x=129.0756&y=35.1796` |
| 좌표 없음(대조군) | — | `x=126.936991&y=37.470614` (= `clientX/clientY`, IP 기반) |
| 쿼리 교체(`주민센터`) | 강남 좌표 | `query=주민센터&x=127.0276&y=37.4979` |

- **확정 템플릿**: `https://map.naver.com/p/search/{encodeURIComponent(query)}?c={lng},{lat},15,0,0,0,dh`
- **좌표 순서는 경도(lng)가 먼저.** 뒤바꾸면 조용히 엉뚱한 위치로 센터링되므로 순서 회귀 테스트를 유닛테스트에 고정한다.
- 쿼리에 독립적으로 동작 → 안마원/주민센터/보건소에 같은 빌더를 재사용해도 된다.
- 좌표를 안 넣으면 전국 뷰가 아니라 **IP 기반 위치**로 센터링된다. 위치권한 거부 시에도 완전히 망가지진 않지만, IP 위치는 통신사에 따라 크게 틀리므로 **시도 선택 폴백은 그대로 유지**한다.
- 모바일 앱스킴(`navermap://`)은 실기기가 없어 **미실측**. 웹 URL을 기본 경로로 두고, 앱스킴은 실패해도 웹으로 열리는 선택적 시도로만 쓴다. 실측은 배포 후 모바일에서.
- 관측된 리스크: 헤드리스 접근 시 DOM에 `ncaptcha-iframe`이 존재. 실사용자의 링크 이동에는 영향 없으나, **이 사이트가 네이버 지도를 스크래핑하거나 서버에서 대신 호출하면 안 되는 근거**다. 우리는 링크 아웃만 한다.

### 9.1 왜 accent가 CTA 배경이 아닌가

`#0d7f6e`는 흰 글씨 기준 **4.91:1**로 AA는 넘지만 §10이 요구하는 AAA(7:1)에 미달한다.
따라서 **솔리드 CTA 배경은 `primary`**(11.95:1)를 쓰고, accent는 아이콘·테두리 같은 비텍스트
강조로 내린다. 본문 링크는 AAA를 만족하는 `--color-link`를 신설해 쓴다.

> 구현 주의: 계획서 Task 5의 `LocationFinder` 버튼이 `bg-accent`로 적혀 있다 → `bg-primary`로 수정.

## 10. 접근성 (신설 — 이 사이트의 1급 요구사항)

이 사이트의 실사용자는 **만 60세 이상 어르신**(수혜자)과 **시각장애인**(제공자)이다.
포트폴리오 4개 사이트 중 접근성이 부차적이지 않은 유일한 사이트이므로, party의 가독성 원칙을
승계하되 **고령자 기준으로 상향**한다. 아래는 전부 Task 13 QA에서 측정 가능한 항목이다.

### 10.1 타이포그래피

- 본문 **18px**(party 16~17px에서 상향), 행간 **1.8**.
- **최소 글자 크기 14px.** party는 푸터·캡션에 12.5px를 쓰는데(`text-[12.5px]`), 복제 시
  전부 14px 이상으로 올린다.
- h1 30px / h2 22px / h3 19px, 위계를 건너뛰지 않는다.
- 본문 최대폭은 px·rem 기반. **`ch` 단위 금지**(한글에서 폭이 튄다 — 프로젝트 표준).
- `word-break: keep-all`로 "안마바우처" 같은 복합명사가 중간에서 쪼개지지 않게 한다.

### 10.2 색·대비

- 본문 텍스트 **AAA(7:1 이상)**, 보조 문구 **AA(4.5:1 이상)**, 아이콘·테두리 등 비텍스트 **3:1 이상**.
- **색 단독 인코딩 금지.** 특히 대상 카드의 「제공자」 뱃지(시각장애인)는 색만으로 구분하지 않고
  **색 + 아이콘 + 텍스트 라벨** 3중으로 인코딩한다. 이 구분이 사이트의 핵심 오해교정 장치다.
- **링크는 상시 밑줄.** 색만으로 링크를 구분하지 않는다.
- **라이트 팔레트 고정.** 다크모드 자동 전환을 넣지 않는다(claim-hub에서 자동전환 버그 경험).

### 10.3 조작

- 터치 타깃 **최소 48×48px**, 인접 타깃 간 간격 8px 이상. 시도 17개 그리드가 특히 위험하다.
  - **예외: 문장 안에 들어간 인라인 링크.** 인라인 링크는 줄 높이를 따르므로 48px로 키우면
    본문 줄간격이 깨진다. WCAG의 타깃 크기 기준도 인라인 링크를 예외로 둔다. 대신 인라인
    링크는 **상시 밑줄 + AAA 대비(`--color-link`)**로 식별성을 확보한다.
    이 예외는 독립 컨트롤(버튼·내비·타일·시도 그리드)에는 적용되지 않는다.
- 포커스 링 2px + offset 2px, 모든 인터랙티브 요소에 키보드로 도달 가능.
- 전화번호는 `tel:` 링크로.
- 브라우저 확대 **200%에서 가로 스크롤 0**.
- 위치 권한 요청 버튼은 무엇이 일어나는지 사전 고지(어르신 대상 — 권한 팝업은 불안 요소).

### 10.4 스코프 밖 (YAGNI)

스크린리더 본격 대응(skip-link, `aria-live`, 랜드마크 role 전면 적용)은 이번 범위가 아니다.
단, 시맨틱 태그(`main`/`nav`/`header`/`footer`)와 `alt` 텍스트는 기본으로 지킨다.

## 11. 키워드 → 페이지 매핑 (신설)

타깃 키워드를 페이지에 **1:1로 배정**해 자기잠식(cannibalization)을 막는다. 한 키워드는 한
페이지만 노린다. 각 페이지의 `<title>`·h1·description·OG 텍스트가 배정 키워드를 축으로 돈다.

| 키워드 | 담당 페이지 | 비고 |
|---|---|---|
| 안마바우처 | `/` | 헤드 키워드. h1 주제어 |
| 정부지원 안마바우처 / **정부지원안마바우처** | `/` | 띄어쓰기·붙여쓰기 **양쪽 표기 모두** 자연 노출 |
| 정부지원 안마서비스 | `/` + `/target/senior` | 제도 정식명은 "시각장애인 안마서비스" → h2로 병기 |
| **출산 안마바우처 / 산모 안마바우처** | `/related/maternity` | **조건부 안내** — 아래 §11.1 |
| 안마바우처 질병코드 / M코드 | `/related/maternity` | 질병코드 표 |
| 어르신 안마바우처 / 노인 안마바우처 | `/target/senior` | |
| 장애인 안마바우처 | `/target/disabled` | |
| 국가유공자 안마 | `/target/veteran` | |
| 시각장애인 안마사 자격 | `/target/blind` | 오해교정(제공자) |
| 안마바우처 신청방법 / 신청자격 | `/guide/apply` | |
| 안마바우처 본인부담금 / 횟수 / 가격 | `/guide/cost` | |
| 국민행복카드 안마 | `/guide/card` | |
| {시도} 시각장애인 안마원 | `/find/[sido]` | 지역 롱테일 17개 |

### 11.1 "출산 안마바우처" 처리 원칙 (2026-08-20 개정)

**"출산 안마바우처"라는 이름의 제도는 없다. 그러나 산모가 신청할 수 없는 것도 아니다.**
(§1.1) 초기 스펙의 "산모는 대상이 아님" 단정은 철회한다.

`/related/maternity`는 **키워드를 제목에 담되, 조건부로 정확하게** 안내한다.

- `<title>`: `출산 안마바우처 — 산모도 신청 가능한가요? 질병코드 조건 정리`
- h1 직하단 `--color-destructive` 배너: "별도 제도는 없다 + 질환 입증 시 가능할 수 있다"를 함께 고지.
- 이어서 (a) 산모의 신청 조건 3블록, (b) **질병코드 표**(M/G/I/R81/E10~E14), (c) 별도 사업인
  산후도우미 안내를 배치한다. `FAQPage` JSON-LD로 3문답을 낸다.
- 롱테일 확장: `안마바우처 질병코드`, `안마바우처 M코드`가 이 페이지에 함께 배정된다.
- **금지**: "산모 전용 안마바우처가 있다"는 식의 단정, 지자체 확인 없이 "신청하면 된다"는 확언,
  "출산 안마바우처 신청방법" 같이 존재하지 않는 제도의 절차를 있는 것처럼 쓰는 문구.

이 방식은 §5 가드레일(정확성·중립성)을 지키면서 검색 의도를 정확한 정보로 충족시킨다.

### 11.2 표기 변형

한국어 검색에서 `정부지원 안마바우처`(띄어쓰기)와 `정부지원안마바우처`(붙여쓰기)는 다르게
처리될 수 있다. 구글은 `keywords` 메타를 무시하지만 네이버는 참조하므로,

- `keywords` 메타에 두 표기를 모두 넣고,
- 본문·h2·FAQ 문장에도 두 표기가 **자연스럽게** 각각 1회 이상 등장하게 쓴다(억지 반복 금지).

## 12. 이미지 · OG · 파비콘 · 검색 썸네일 (신설)

### 12.1 이미지 트랙을 둘로 나누는 이유

구글은 검색·Discover 썸네일을 og:image·schema.org `image`·본문 이미지에서 **자동 선택**하면서,
동시에 **"텍스트가 들어간 이미지와 로고 같은 범용 이미지는 피하라"**고 안내한다. 그런데 카카오톡·
네이버 공유 미리보기용 OG는 키워드 텍스트가 커야 효과가 있다. 두 요구가 충돌하므로 트랙을 분리한다.

| 트랙 | 용도 | 규격 | 텍스트 |
|---|---|---|---|
| **A. OG 카드** | 카카오톡·네이버·X 공유 미리보기 | 1200×630, 페이지마다 고유 | 키워드 **크게** 넣음 |
| **B. 대표 이미지** | 구글/Discover 검색 썸네일 후보, JSON-LD `image` | 1:1 / 4:3 / 16:9 3종, ≥300,000px | **텍스트 최소** |

### 12.2 트랙 A — OG 카드 (27개 전부 고유)

`next/og` `ImageResponse`로 생성. 현재 계획서는 루트+대상4 = 5개만 두는데, **전 27페이지로 확장**한다.

- `app/opengraph-image.tsx` — 허브
- `app/target/[slug]/opengraph-image.tsx` — 4개
- `app/guide/[topic]/opengraph-image.tsx` — 3개
- `app/related/maternity/opengraph-image.tsx` — 1개
- `app/find/opengraph-image.tsx` — 1개
- `app/find/[sido]/opengraph-image.tsx` — 17개
- 동적 라우트의 OG는 **페이지와 별도로 `generateStaticParams`를 선언**해야 정적으로 빠진다(안 하면 `ƒ Dynamic`).
- 폰트는 **ttf만**(`pt-extrabold.ttf`, `pt-medium.ttf`) — next/og는 woff2를 못 읽는다. party에 두 파일 존재 확인됨.
- 레이아웃: `primary`(#0f3d3e) 배경 + 좌측 정렬, 상단에 배정 키워드(72~92px extrabold), 하단에
  보조 문구(32~36px medium), 우상단 라디얼 그라디언트 악센트. party OG 구조 승계.

### 12.3 트랙 B — 대표 이미지 (검색 썸네일 후보)

**페이지 유형 10종**(허브 / 대상4 / 가이드3 / maternity / find) **× 3비율 = 30개** PNG를
`public/thumb/{type}-{1x1|4x3|16x9}.png`로 사전 생성해 커밋한다. 지역 17페이지는 `find` 세트를 공용.

- 생성: `scripts/build_thumbnails.mjs` — SVG 소스를 **헤드리스 Chrome `--screenshot`**으로 PNG 변환.
  이미 로컬에 Chrome이 있고 이 방식으로 SPIKE도 수행했으므로 **새 의존성 0**. 재실행으로 재현 가능.
- 내용: 아이콘·도형 기반 일러스트(예: 손·온기·지도 핀·카드). **사진 금지, 텍스트 최소**(브랜드명 정도).
- 각 페이지 본문 상단에 해당 16:9 이미지를 **실제 `<img>`로 1장** 배치(`alt`는 페이지 주제 서술).
  인라인 SVG로는 크롤러가 독립 이미지 URL로 인식하지 못해 썸네일 후보가 되지 않는다.
- JSON-LD에 3비율 배열로 지정: `image: ["/thumb/x-1x1.png", "/thumb/x-4x3.png", "/thumb/x-16x9.png"]`.
- `max-image-preview:large`는 party layout의 `robots.googleBot`에 이미 있음 → 승계 확인만.

### 12.4 콘텐츠 안전 가드레일 (이 니치 고유)

"안마" 키워드는 성인 업소 스팸과 검색 공간이 인접한다. 오분류는 AdSense 승인 자체를 위협한다.

- **서브도메인을 `anma`가 아닌 `care`로 둔다(확정).** URL 문자열의 "anma"는 광고 브랜드안전
  분류기와 어르신 사용자 양쪽에서 업소 오인을 유발할 수 있는데, 서브도메인 문자열이 한국어 키워드
  랭킹에 주는 영향은 사실상 없다 — 잃을 SEO 없이 리스크만 줄인다. 형제 사이트의 짧은 영어 일반명사
  규칙(`claim`/`finance`/`party`)과도 일치한다.
  **브랜드명은 "안마바로"를 유지한다** — 페이지 `<title>`·본문에는 `안마바우처` 키워드가 반드시
  들어가야 검색에 잡히므로, 리스크는 URL 레이어에서만 걷어내고 콘텐츠 레이어는 그대로 둔다.
- **이미지에 사람 신체·마사지 장면 사진 금지.** 아이콘/일러스트만.
- OG·썸네일·`alt`에 "출장", "1인샵", "예약" 등 업소 연상 표현 금지.
- 항상 "정부지원", "시각장애인 안마사", "바우처" 같은 제도 맥락 어휘와 함께 쓴다.

### 12.5 파비콘 (구글 검색 결과 노출)

구글 공식 요건 확인 결과: **정사각(1:1), 최소 8×8px, 48×48보다 크게 권장, URL이 안정적일 것**,
`rel="icon"`/`apple-touch-icon` 인식, 홈페이지 `<head>`에서 발견되며 Googlebot-Image 크롤 허용 필요.
("48px의 배수여야 한다"는 통설은 현행 문서 기준 사실이 아니다.)

- `app/icon.tsx`의 size를 party의 **32×32 → 96×96으로 상향**(권장치 초과).
- `app/apple-icon.tsx` 180×180 유지.
- `manifest.ts`의 아이콘 목록도 96/192/512로 맞춘다.
- 심볼: 브랜드 이니셜 "안" 또는 lucide `HandHelping` 계열. 배경 `primary`(#0f3d3e), 글리프 흰색.
- **URL 안정성**: 한번 배포한 뒤 아이콘 라우트 경로를 바꾸지 않는다(구글 재수집이 느리다).
- `robots.txt`가 `/icon`·`/apple-icon`·`/thumb/`를 막지 않는지 확인(현 정책은 `Allow: /`라 문제없음).

### 12.6 배포 체크리스트에 추가된 미해결 항목

- party의 `public/ads.txt`에는 Google 라인만 있고 **Taboola 라인이 없다.** 의도된 구성인지
  Taboola 대시보드에서 확인 후 필요하면 추가한다. (임의로 라인을 만들지 않는다.)
